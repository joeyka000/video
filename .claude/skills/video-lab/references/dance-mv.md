# 迷幻風卡點跳舞 MV ＋ 複雜度底線

使用者給了一份迷幻風卡點跳舞 MV 的完整描述，並要求「之後的影片至少複雜到這種程度」（2026-11-12）。這份文件分兩部分：
〈零〉從那份描述抽出來、每支片都適用的**複雜度底線**；〈一〉～〈六〉是這個類型的完整配方。
工具：`scripts/songcut.py`（歌剪成 90 秒）、`scripts/keyloop.py`（立繪綠幕、摳像循環、實拍去背成舞步）、`scripts/psyfx.py`（迷幻零件）、
`scripts/beatqa.py`（閃白落點與音畫同步）、`templates/dance_mv.py`（引擎範本）、`templates/music_dance.py`（原創舞曲＋精確拍格）。

---

## 零、複雜度底線（所有新片，不只跳舞 MV）

那份描述厲害的地方不是招式多，是**每一層畫面都有自己的時間規則，而且全部綁在歌的結構上**，再加上「哪裡不准用」的留白。
開新片時，plan.md 要寫出下面七項，少一項就還沒到底線：

1. **至少四層、每層一條時間規則**：背景層、中景（字、圖形）、主體、前景特效。每層寫「多久變一次、在哪個音樂位置變」。
   例：背景每小節換、字主歌每 2 小節／副歌每小節換、主體每 4 小節換人、特效只在小節線上。
2. **結構從歌長出來**：歌先剪成前奏／主歌／副歌／結尾（`songcut.py`，剪點在小節線、結尾是原曲的收尾不是硬淡出），
   段落決定每一層的規則怎麼變（副歌密度、陣型、轉色）。
3. **至少六種手法，每種寫「只用在哪裡」**：留白是規格的一部分（閃白只在小節線、撕裂只在換人與副歌小節頭、
   萬花筒只在前奏收尾／副歌每段最後一小節／結尾）。寫不出「只用在哪裡」的手法就刪掉。
4. **主體有景別變化**：同一個主體在一段裡至少換一次取景（全身 → 半身 → 特寫），推鏡平順、特寫在拍上硬切。
5. **一份可重跑的一鍵指令**：素材規格、成片規格、每層規則、特效分寸、流程要求寫成一段 brief（〈五〉是範本），
   換素材就能整支重做。
6. **輸出前自動檢查**：縮圖總覽與剪點關卡（review.md）之外，卡點片加 `beatqa.py`：閃白有沒有落在小節線、
   音畫有沒有同步（混音位移 ±1 格內）。
7. **交付回報**：檔名、長度、規格、歌曲剪接點在第幾秒、花了多少（點數／美元）、哪些是自己補的假設。

實拍旅遊片也照這七項，只是第 1 項的層是「實拍、字卡、光、轉場」，第 3 項的留白照 `masters.md`〈零〉（特效升級實拍、不取代）。

## 一、素材規格

| 素材 | 規格 | 我們怎麼處理 |
|---|---|---|
| 歌 | 1 個 mp3，長度不限（例：Suno 生成 2 分 24 秒） | `analyze.py` → `songcut.py --dur 90` 剪成 90 秒 |
| 角色立繪 | 白底或純色底、全身、直式，每位 1 張（例：Midjourney 6 張） | `keyloop.py plate`：去背、去地面陰影、9:16 綠幕（衣服有綠就藍幕） |
| 背景圖 | 橫式 16:9，越花越好，10 張以上（例：27 張） | 引擎裡色相流轉＋輕微扭曲，每小節輪流 |
| 跳舞影片 | 每位 1 段 5 秒、480p、首尾幀同一張（無縫循環） | 見〈二〉生成；`keyloop.py key` 摳像、加貼紙描邊、抓舞步節拍 |

雲端 session 沒有使用者電腦上的生成工具。跳舞影片四條路，**每一條花錢的都先報總額、等使用者同意這一筆**（CLAUDE.md）：
1. **即夢 Dreamina（Seedance 首尾幀模式）**：使用者電腦上的 `dreamina-canvas` CLI（已登入、有點數）。在雲端 session 用
   Remote Control 連到那台電腦的資料夾（`list_computer_folders` → `request_computer_folder`），在那邊跑 CLI；
   送出前報總點數（例：6 段共 360 點），同意後才送。
2. **Veo 3.1（首尾幀）**：`veo/veo.py`，金鑰走雲端環境的 Network secret；先 lite 720p 試一段，再定稿。
3. **實拍去背（不花錢，真的動作）**：使用者說「用你能用的方式做」時走這條。從使用者自己的素材找全身在動的影片與連拍：
   - 影片 → `keyloop.py matte`：逐格 ISNet 去背，把人固定在原地、同樣大小（朝鏡頭走過來變成原地踏步、轉圈留在原地），
     來回播（boomerang），並把「手腳伸最開、動作停住」的格對到每一拍（`marks`）。一趟的拍數取 4 的倍數（一趟＝整數小節）。
   - 連拍照片 → `keyloop.py burst`：每張去背成一個姿勢，每拍換一張（換的那一下壓扁再彈起來）。
   - 不同天的穿搭＝不同角色；影片（連續動作）與連拍（每拍換姿勢）交錯排。找素材的方法見〈七〉。
4. **免費律動（puppet）**：連會動的素材都沒有時，`psyfx.Dancer` 用立繪做彈跳、搖擺、跳躍、點頭、扭動、機器人六種律動，
   全部落在拍頭。給試片、排版、抓節奏用；交付時要講清楚這是替代版，品質比不上真的舞蹈。

歌也一樣：沒有 Suno 時用 `templates/music_dance.py` 合成原創舞曲（128 BPM、48 小節＝90 秒），直接輸出精確拍格 json，
不用做拍點偵測（真實歌曲的拍格要校正，見〈二〉）；交付時主動說「有想用的歌給我就換」。

生成提示詞（每位角色）：固定鏡頭、全身入鏡、角色全程看著鏡頭、背景維持純色、跟著歌曲 BPM 在原地跳舞、每位舞風不同；
首幀與尾幀用同一張 `<名>_plate.png`。

## 二、流程

```
python scripts/analyze.py song.mp3 -o work/song.json
python scripts/songcut.py song.mp3 work/song.json --dur 90 -o work/song90.wav      # 先 --plan 看段落角色，判錯用 --roles 改
python scripts/keyloop.py plate 跳舞素材/*.png -o work/chars
#   → 生成（〈一〉三條路之一；花錢先問）→ 每段影片：
python scripts/keyloop.py key 生成/A.mp4 -o work/chars/A_clip --bpm <歌的 BPM>
cp templates/dance_mv.py work/engine.py                                            # 只改「設定」那一段
python scripts/frames.py sheet work/engine.py -o qa/sheet.jpg   → 評分 → review.py gate
python scripts/flow.py check --engine work/engine.py -o qa/flow → 評分 → review.py gate
python scripts/frames.py video work/engine.py -o qa/test.mp4 --from <副歌前 3 秒> --to <後 7 秒>
python scripts/beatqa.py qa/test.mp4 --audio-json work/song90.json --song work/song90.wav --offset <from>
python scripts/frames.py video work/engine.py -o deliver/master.mp4                # 背景跑；1280×720 約 0.15 秒／格
python scripts/frames.py deliver deliver/master.mp4 -o deliver/<名>.mp4
python scripts/beatqa.py deliver/<名>.mp4 --audio-json work/song90.json --song work/song90.wav
```

`songcut.py` 一定會做兩件事（Sparkle 實測後加的）：
- **逐段相位校正**：analyze.py 假設整首速度固定，現場錄音的長歌過門放慢後整段會錯開（Sparkle 420 秒後大鼓全部晚 +175 ms，
  約 1/3 拍）。每段用大鼓殘差中位數平移；量不到的段沿用前一段。
- **拍格鎖到鼓的攻擊點**：每 16 拍一個視窗量殘差、平滑後套用。沒有鼓的視窗用 onset 強度，但 onset 強度峰值比鼓晚
  30–50 ms（實測 48 ms），要扣掉、而且最多動 ±50 ms（鋼琴、人聲會把拍格拉歪）。
  結果：大鼓、小鼓都在拍格 +10 ms 內；beatqa 的「歌本身對拍格」約 +30～+60 ms 是 onset 強度的偏差，正常。

## 三、剪輯節奏（引擎範本已寫成規則）

| 規則 | 做法 |
|---|---|
| 換人 | 每位角色停留 4 小節，換人落在小節線上；角色圖層「滑動＋交叉淡化」，小節線前後各半拍，不硬切 |
| 取景 | 同一位角色：前兩小節全身 → 第三小節前 60% 平順推到半身；每隔一位，最後兩拍在拍上硬切到眼睛特寫（焦點跟著律動後的眼睛） |
| 副歌陣型 | 開頭與結尾全員並排（各 2 小節）；中間輪流：單人 4 → 雙人並排 2 → 單人 4 → 五連排變色 2；剩不到 2 小節併進結尾 |
| 跟拍 | 生成的舞：循環伸縮成整數拍，落拍格對齊歌的拍點；全員並排不錯開（錯開就不卡點） |
| 弱起 | 不到半小節的弱起併進第一小節（不然 0.3 秒會出現一個只換色相的假剪點） |
| 剪點表 | `SHOTS` 照實寫：每小節換背景＝每小節一刀，眼睛特寫是小節中間的一刀（flow.py 的平均鏡頭長才算得對） |

## 四、特效分寸（要留白）

| 特效 | 只用在 | 強度（實測後定的） |
|---|---|---|
| 閃白 | 小節線上 | 換人 0.30、副歌小節頭 0.18、其他 0.09；約 3 格消退（0.55 時換人那格整片發白） |
| 背景 | 每小節換一個 | 資料夾圖片（色相流轉 36°/秒＋同圖色相波 110°＋扭曲 6 px）兩張、程式圖樣一個輪流；萬花筒小節把背景摺成 8 瓣 |
| 撕裂＋RGB 分離 | 換人、副歌小節頭 | 換人 0.35、副歌 0.2，下一拍（0.8 拍）前歸零；0.85 時整格亂掉，使用者原話是「輕輕出現」 |
| 萬花筒 | 前奏最後一小節、副歌每 8 小節最後一小節、結尾兩小節 | 只摺背景，角色疊在上面保持清楚 |
| 副歌轉色 | 整個副歌 | 背景與大字轉色相 22°/秒；插畫角色跟著整圈轉，真人角色只擺 ±24° |
| 背景日文大字 | 主歌每 2 小節一個、副歌每小節一個 | 字高 46%、最寬 78%、不透明度 0.88、細描邊；在小節線上從 1.22 倍彈到 1 倍、不淡入。60% 時跟角色搶畫面 |
| 貼紙描邊 | 所有角色 | 白邊約角色高 1.2%＋往右下的淡投影 |
| 殘影 | 副歌單人段 | 兩道純色剪影（半拍前 0.45、四分之一拍前 0.7），顏色隨時間轉；眼睛特寫時關掉 |
| 片尾 | 最後 1 秒 | 收進深紫（淡出只留給片尾） |

大字從歌的主題挑關鍵字（例：夢、光、火花、運命），或用使用者指定的字，或不放；**不做逐句歌詞字幕**。
字型：Dela Gothic One、RocknRoll One、Rampart One（OFL，啟動腳本會下載），保底 Noto Sans CJK JP。

## 五、一鍵指令範本（使用者給的，存下來重用）

```
用我上傳的歌做一支「迷幻風卡點跳舞 MV」。
【素材】歌曲：這次上傳的 mp3。角色：「跳舞素材」資料夾的立繪，每張一位。背景：「背景素材」資料夾的圖片，全部輪流用。
【規格】成片 [90] 秒、[16:9 橫式]、1280×720、30fps、MP4，存回「跳舞素材」資料夾。先分析 BPM、拍點、小節線和段落，
  把歌剪成 [90] 秒：要有前奏、主歌、副歌和自然的結尾，剪接點落在小節線上。
【跳舞素材】立繪去背、去地面陰影，換成純綠幕 9:16（衣服有綠色改藍幕）。每位生成 1 段循環跳舞：[Seedance 2.5]、[480p]、[5] 秒、
  首尾幀同一張；固定鏡頭、全身入鏡、全程看鏡頭、背景純色、跟著 BPM 原地跳、每位舞風不同。送出前先報總點數，同意後再生成。
  生成後去背，加白色貼紙描邊。
【剪輯節奏】每位停留 [4] 小節再換人，跳舞跟拍點同步；換人落在小節線上，滑動＋交叉淡化，不硬切；同一位中間換一次取景
  （全身↔半身平順推鏡，偶爾接眼睛特寫）；副歌開頭和結尾全員並排，副歌穿插雙人並排、五連排變色。
【特效，要留白】閃白只在小節線上（換人稍強、其餘很淡）；背景加色相流轉和輕微扭曲，穿插彩虹同心圓、旋轉色環、融化彩虹、
  條紋、黑白棋盤，每小節換一個；副歌整個畫面連角色慢慢變色；撕裂＋RGB 分離只在換人和副歌小節頭輕輕出現、下一拍前恢復；
  萬花筒用在前奏收尾、副歌每段最後一小節和結尾，角色疊在上面保持清楚；背景日文大字放角色後面，主歌每 2 小節一個、
  副歌每小節一個，內容 [從歌曲主題挑關鍵字 ／ 指定的字 ／ 不放字]，不要逐句歌詞字幕。
【流程】不確定的地方（長度、比例、模型、點數）一次問完再開始；輸出前檢查閃白是否落在小節線、音畫是否同步；
  完成後告訴我檔名、長度、歌曲剪接點在第幾秒、花了多少點數。
```

這段 brief 的寫法本身就是範本：**素材 → 規格 → 生成 → 節奏 → 特效（含留白）→ 流程**，每一條都能變成引擎裡的一條規則。
接其他類型的片，也照這個順序把使用者的需求寫成 brief，再寫進 plan.md。

## 七、實拍當舞步：找素材與踩過的坑（釜山真人舞步版，2026-11-12）

找素材（1,379 張照片、26 支影片 → 6 位角色，約 30 分鐘）：
- 影片：每支出 8 格縮圖條，找「全身、人在動、腳沒出鏡」的：走過來、轉圈、跑過來都能用；半身自拍、手部特寫不能用。
- 連拍：拍攝時間間隔 ≤ 4 秒的照片歸成一組（≥ 5 張），每組抽頭、中、尾三張跑 YuNet：剛好一張臉、臉高 < 畫面 10% 的是全身單人連拍。
- `keyloop.py burst` 出完一定要看姿勢總覽，手動挑掉：蹲下的、往鏡頭靠的（從上往下拍會頭大身體小）、去背把欄杆或車子黏進來的。

踩過的坑：
- **大小正規化**：影片用平滑過的身高（σ 0.5 秒）就好。照片試了三種：全用臉高（YuNet 臉框 ±8% 雜訊，遠的那組整組小 12%）→
  依相鄰身高差分組（攝影者慢慢後退時組內大小不一）→ **輪廓高度與臉高換算差 10% 內信輪廓高度，否則用臉高**（定案）。
- **真人不能整圈轉色相**：規格的「副歌整個畫面連角色一起變色」用在真人會變綠臉紫臉。`CHAR_HUE = 24`：背景照轉，人只擺 ±24°。
  五連排變色維持（人小、是普普風的花招）。
- **殘影用純色剪影**：半透明的照片殘影看起來像對不準的鬼影；改成半拍前、四分之一拍前的自己填純色，乾淨、還看得出上一個姿勢。只在副歌單人段用。
- **半身鏡頭要跟著頭**（`TRACK_HEAD`）：轉圈、彎腰時固定取景會只拍到大衣。
- **來源身高 < 600 px 的角色不做眼睛特寫**（放大 3.6 倍會糊）；連拍照片來源身高約 2000 px，特寫最清楚。
- **暗的照片摺萬花筒會整片黑**：結尾全員並排改用程式圖樣當底。
- **快取要設上限**：全尺寸角色一格 float32 約 21 MB；預乘快取 256 筆 × 4 個渲染行程會吃光 16 GB（被系統砍掉）。現在 24 筆。
- 單人段的輪替：雙人與五連排不佔輪替，每位角色才都輪得到單人段。

## 六、實測教訓（釜山示範片，2026-11-12）

- `analyze.py` 的 tempo 粗估原本對全解析度 onset 做 tempogram，9 分鐘的歌要 20 GB 以上記憶體（3 分鐘 8 GB）→ 降 8 倍取樣，1.8 GB、結果相同。
- 去地面陰影只看顏色會把黑裙下襬、白襪一起刪掉；ISNet 本身幾乎不收陰影（合成測試主體外 > 0.5 的只有 201 px），
  所以只清 ISNet 不確定（alpha < 0.9）的部分。
- 放大用立方插值會超出 0–1，沒 clip 就寫成 uint8 會溢位，白色毛帽變成藍白雜點。
- 迷幻色相流轉用在風景、圖樣、食物都好看，用在有人臉的照片會變成綠臉；背景資料夾挑沒有人的圖。
- 抽格點不要放在換人那一格（閃白＋撕裂＋交叉正在最亂的時候）：換人後半拍＋2 格才是新鏡頭第一個清楚畫面，轉場正中另抽一兩格就好。
- finish.py 在這個類型會標很多「色階」「高光硬切」：彩虹條紋、色環是刻意的平塗色塊，棋盤、貼紙白邊、白色大字是刻意的純白；
